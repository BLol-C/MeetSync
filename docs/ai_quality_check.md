# วิธีตรวจคุณภาพรายงานที่ AI ร่าง (ตอบคำถามอาจารย์: "ข้อมูลที่ AI ทำออกมาน่าเชื่อถือแค่ไหน")

หลักการ: **คนที่อยู่ในประชุมเป็นผู้ตัดสิน ไม่ใช้ AI ตัดสิน AI** ระบบช่วยแค่ให้ตรวจเป็นระบบและนับผลได้

## ขั้นตอนต่อหนึ่งประชุม

1. ประชุมจริงตามปกติ → ตรวจ transcript → ให้ AI ร่างรายงาน (แท็บ ④) **ก่อนแก้อะไรในรายงาน**
   (ฉบับ AI เดิมถูกเก็บใน `ai_snapshot` เสมอ แก้ทีหลังก็ยังเทียบได้ แต่ถ้ากด "สร้างใหม่" ฉบับเดิมจะถูกแทนที่)
2. สร้างใบตรวจ
   ```
   .\venv\Scripts\python.exe tools\review_sheet.py <เลขประชุม>
   ```
   ได้ไฟล์ `ai_review\meeting_<เลข>.md` (โฟลเดอร์นี้ไม่ถูก commit เพราะมีเนื้อหาประชุมจริง)
3. ผู้ที่อยู่ในประชุมเปิดไฟล์นั้น ติด `[x]` ในแต่ละวาระและแต่ละงาน (ข้อความอ้างอิงแนบให้แล้ว ตรวจเทียบ transcript ท้ายไฟล์ได้)
4. เขียนสิ่งที่ AI ตกหล่นในข้อ 4 แล้วกรอกตารางรวมคะแนนข้อ 5
5. ค่อยแก้รายงานและอนุมัติตามปกติ (ข้อ 1 ของใบตรวจจะนับให้อัตโนมัติว่าคนแก้อะไรไปบ้าง)

## ตัวชี้วัดที่ใช้ (เรียงจากร้ายแรงสุด)

| ตัวชี้วัด | ความหมาย | ทำไมสำคัญ |
|---|---|---|
| วาระที่ **แต่งมติ** | ที่ประชุมไม่ได้ลงมติ แต่ AI เขียนมติ | รายงานทางการผิดความจริง |
| งานที่ **ไม่มีจริง** | AI แต่งงานขึ้น | ส่งเข้า Calendar ของคนผิด |
| งานที่ **เดาวัน** | ไม่มีใครพูดถึงวัน แต่ AI ใส่วัน | นัดผิดวัน |
| ผู้รับผิดชอบ/วันที่ถูก | ตรงกับที่ตกลง | |
| เนื้อหาวาระถูก | สรุปตรงกับที่พูด | |
| วาระที่ตกหล่น | พูดจริงแต่ไม่อยู่ในรายงาน | |
| อ้างอิงที่ไม่มีใน transcript | ระบบตรวจให้อัตโนมัติ (คำเตือนแท็บ ④) | |

## วิธีรายงานผลให้น่าเชื่อถือ (ห้ามอ้างเกินจริง)

- ใช้ประชุมจริงอย่างน้อย 3–5 ครั้งที่ต่างกัน (มีมติ / ไม่มีมติ / มีงานระบุคนและวัน) และบอกจำนวนประชุมกับจำนวนวาระ/งานทั้งหมดเสมอ
  เช่น "จาก 4 ประชุม 17 วาระ แต่งมติ 1 วาระ" ไม่ใช่เปอร์เซ็นต์ลอยๆ
- ตัวอย่างน้อยเกินกว่าจะเป็นสถิติ เขียนเป็น "ผลจากการทดสอบเบื้องต้น" และระบุว่าผลขึ้นกับโมเดล Gemini
- ระบุโมเดลและเวอร์ชัน prompt ที่ใช้ (ใบตรวจพิมพ์ให้แล้ว) ผลของ prompt เก่าห้ามอ้างกับ prompt ใหม่
- ถ้าแก้ prompt แล้วผลดีขึ้น ให้เก็บใบตรวจก่อน-หลังไว้เทียบ (ระบบเก็บเวอร์ชัน prompt ไว้ในรายงานแล้ว)
- เสียงจาก Meet ที่ CC ถอดผิดทำให้ AI สรุปผิดตามได้ ใบตรวจนี้ตรวจเทียบ transcript ที่คนยืนยันแล้ว
  ถ้าผิดที่ transcript ให้จดเป็นหมายเหตุ ไม่นับเป็นความผิดของ AI

## ระบบมีกลไกป้องกันอะไรบ้าง (ไม่ขึ้นกับตัวเลขข้างบน)

- ทุกมติ/งานต้องมีข้อความอ้างอิงที่คัดลอกจาก transcript ระบบตรวจว่ามีอยู่จริง ไม่เจอ = เตือน
- ผู้รับผิดชอบต้องอยู่ในรายชื่อผู้เข้าร่วม; วันที่ต้องอ่านได้และสมเหตุผล; คำเตือนตัวเลขกำกวม
- คนตรวจ transcript ก่อน AI สรุป, ตรวจและแก้รายงานหลัง AI ร่าง, ประธาน/เลขาอนุมัติ — AI ออกรายงานฉบับจริงเองไม่ได้
- PDF ก่อนอนุมัติมีลายน้ำ "ฉบับร่าง"
