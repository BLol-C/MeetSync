ใช้ควบคู่กับ `docs/proposal_round4.md` (เลขหน้าอ้างฉบับ 48 หน้า `..._test.pdf`) ข้อความ "แก้เป็น" วางลง Proposal ได้
**ใช้เมื่อฟีเจอร์นี้อยู่ใน `main` แล้วเท่านั้น** (ตอนเขียนไฟล์นี้อยู่ที่สาขา `agenda-sections` ยังไม่ merge) ถ้าไม่ส่งฟีเจอร์นี้ ให้ข้ามไฟล์นี้ทั้งหมด

## สรุปฟีเจอร์ (สิ่งที่ระบบทำจริง ตรวจด้วยเทสต์แล้ว 168 ตัวผ่าน)

- แต่ละเรื่องในรายงานมีช่อง "อยู่ในวาระ" 5 ค่า: `inform` (วาระ 1 เรื่องแจ้งให้ที่ประชุมทราบ), `approve_prev` (วาระ 2 รับรองรายงานครั้งก่อน), `followup` (วาระ 3 เรื่องสืบเนื่อง), `consider_old` (วาระ 4.1 เรื่องค้างพิจารณา), `consider_new` (วาระ 4.2 เรื่องพิจารณาใหม่ — ค่าเริ่มต้นของเรื่องที่ AI สรุป) ส่วนวาระ 5 เรื่องอื่น ๆ เป็นข้อความ `other_matters` เดิม
- PDF วางเรื่องตามวาระที่เลือก (เดิมใส่ทุกเรื่องที่ 4.2)
- ผู้ใช้เลือก "การประชุมครั้งก่อน" ได้ (เฉพาะการประชุมที่ **อนุมัติรายงานแล้ว** และผู้ใช้จัดการได้) เมื่อกด "ให้ AI ร่างรายงาน" ระบบเติมจากฐานข้อมูล **ไม่ผ่าน AI**: วาระ 2 = หัวข้อ "รับรองรายงานการประชุมครั้งที่ … เมื่อวันที่ …" จากครั้งก่อน, วาระ 3 = งานที่มอบหมาย (`action_items`) ของครั้งก่อนทุกรายการ, วาระ 4.1 = วาระของครั้งก่อนที่ไม่มีมติ
- **AI ยังไม่จำแนก** แจ้งทราบ/พิจารณา ผู้ใช้ย้ายเรื่องไปวาระ 1 เองในแท็บรายงาน
- ข้อมูลที่ระบบ **ไม่รู้**: งานครั้งก่อนเสร็จหรือยัง (ไม่มีสถานะ "เสร็จ" ในฐานข้อมูล) และเรื่องที่ไม่มีมติค้างจริงหรือแค่แจ้งทราบ จึงให้คนตรวจและลบ/แก้เอง มติรับรองรายงานให้คนกรอกเอง
- ความถูกต้อง: ตรวจหลักฐานอ้างอิงจาก transcript เฉพาะเรื่องที่ AI สรุป (วาระ 1 และ 4.2) เรื่องที่ระบบเติมหรือคนเพิ่มเองไม่ถูกเตือนเรื่องหลักฐาน `ai_snapshot` เก็บเฉพาะฉบับที่ AI ร่าง

## ที่ต้องทำกับระบบจริงของคุณ
ฐานข้อมูล `meetsync` ที่ใช้อยู่ต้องเพิ่มสองคอลัมน์ก่อนเปิดโค้ดสาขานี้ (ผมทดลองบนฐานข้อมูลชั่วคราวแล้ว ผ่าน):
```sql
ALTER TABLE agenda_items ADD COLUMN section VARCHAR(20) NOT NULL DEFAULT 'consider_new' AFTER order_no;
ALTER TABLE meetings ADD COLUMN previous_meeting_id INT NULL AFTER status;
ALTER TABLE meetings ADD CONSTRAINT fk_meetings_previous FOREIGN KEY (previous_meeting_id) REFERENCES meetings(meeting_id) ON DELETE SET NULL;
```
ข้อมูลเดิมไม่หาย: รายงานเดิมทุกเรื่องกลายเป็น `consider_new` (4.2) ซึ่งตรงกับที่เคยแสดง

## เพิ่มเติม: ฟิลด์ "ตำแหน่ง" ของผู้เข้าร่วม (`speakers.position`)

**พฤติกรรม:** ผู้เข้าร่วมแต่ละคนกรอกตำแหน่งได้ (ไม่บังคับ ไม่เกิน 100 ตัวอักษร) ในตารางผู้เข้าร่วม (หน้าสร้างการประชุมและแท็บ ①) PDF แสดงในคอลัมน์ "ตำแหน่ง" ข้างชื่อผู้มาประชุม: ถ้ากรอกไว้ใช้ตำแหน่งที่กรอก ถ้าเว้นว่างใช้บทบาทในที่ประชุมแทน (ประธาน/เลขานุการ/กรรมการ) ผู้เข้าร่วมที่ไม่ใช่กรรมการแสดงตำแหน่งเฉพาะเมื่อกรอกไว้ ส่วนผู้ไม่มาประชุมแสดงสาเหตุแทน (ไม่แสดงตำแหน่ง)

## เพิ่มเติม: บอทอ่านรายชื่อคนในห้อง (สาขา `participant-scan`)

**พฤติกรรม:** ระหว่างประชุม บอทอ่านรายชื่อจากแผง "ผู้คน" ของ Google Meet ทุกประมาณ 60 วินาที แล้วตั้งสถานะ "เข้าร่วม" ให้ผู้เข้าร่วมที่ลงทะเบียนไว้และชื่อตรงกัน แม้ไม่ได้พูด (เปลี่ยนเฉพาะที่ยังเป็น "ยังไม่ยืนยัน" ไม่เปลี่ยนที่ผู้ใช้ตั้ง "ไม่มา" เอง ไม่สร้างผู้เข้าร่วมใหม่จากชื่อที่ไม่รู้จัก) ถ้าอ่านรายชื่อไม่ได้ ระบบแจ้งในสถานะบอทและไม่กระทบการจับคำบรรยาย

### เพิ่มเติม (สาขา `unconfirmed-matching`): จับคู่ผู้ที่ยังไม่ยืนยันกับชื่อที่เห็นในห้อง

- ชื่อในห้องที่ไม่ตรงกับใครถูกเก็บเป็นผู้เข้าร่วมแยก (`speakers.source = 'meet'`, บทบาท guest, เข้าร่วม, ไม่มีข้อความ) แทนการทิ้ง และแถวของบอทเอง (มี "(คุณ)") ไม่ถูกนับ
- แท็บ ③ มีหัวข้อ "ผู้เข้าร่วมที่ยังไม่ยืนยันการเข้าร่วม": ผู้ที่ลงทะเบียนไว้แต่ยัง `invited` เลือกได้ว่าตรงกับชื่อใดที่เห็นใน Meet (รวมแล้วจำ `meet_alias`) หรือกำหนดเองว่า มา/ไม่มา ที่ยังไม่ได้ตั้งจะถูกบันทึกเป็นไม่มาตอนยืนยัน transcript
- ที่ต้องแก้ใน Proposal เพิ่มจาก P1–P5: **P6** Process 4 (หน้า 22, ภาพ + ข้อความ) เพิ่มกระแสข้อมูล `เลือกจับคู่ชื่อใน Meet / กำหนดสถานะ` จาก Host และการเขียน `meet_alias`, `attendance` ลง speakers table; **P7** คำอธิบาย `source` และ `meet_alias` (หน้า 31) บอกว่าชื่อในห้องที่ไม่ตรงกับใครถูกเก็บให้จับคู่
- ไม่มีคอลัมน์หรือตารางใหม่ในฐานข้อมูล

### เพิ่มเติม (สาขา `roster-and-alias`): "ชื่อใน Meet" และคัดลอกรายชื่อจากครั้งก่อน

- ตารางผู้เข้าร่วมมีคอลัมน์ "ชื่อภาษาไทย" (`speakers.display_name` ชื่อที่ขึ้นในรายงาน) และ "ชื่อภาษาอังกฤษ" (`speakers.meet_alias` ชื่อที่ Meet แสดง ที่มีอยู่เดิม ตอนนี้กรอกได้ตั้งแต่ลงทะเบียน) ใช้จับคู่คนพูดและรายชื่อในห้อง รายงาน PDF ใช้ชื่อที่ลงทะเบียน (ไทย) เสมอ
- เมื่อเลือกการประชุมครั้งก่อน คัดลอกรายชื่อผู้เข้าร่วมที่ลงทะเบียนไว้ (ชื่อ ชื่อใน Meet อีเมล บทบาท ตำแหน่ง) มาที่การประชุมใหม่ได้ ไม่คัดลอกสถานะมา/ไม่มาและสาเหตุ (ประธาน/เลขาตั้งเป็นเข้าร่วม ที่เหลือยังไม่ยืนยัน) ไม่เพิ่มซ้ำคนที่ชื่อหรือชื่อใน Meet ตรงกับที่มีอยู่ และถ้ามีประธาน/เลขาแล้วจะไม่เพิ่มคนที่สองของบทบาทเดียวกัน
- แก้ Proposal เพิ่ม: **Q1** คำอธิบาย `meet_alias` (หน้า 31) บอกว่ากรอกได้ตอนลงทะเบียนและคัดลอกข้ามการประชุมได้ **Q2** ขั้นตอนที่ 2 (หน้า 13) และ Process 2 (หน้า 20, ภาพ + ข้อความ): Host เลือกคัดลอกรายชื่อจากการประชุมครั้งก่อน (อ่านจาก speakers table ของครั้งก่อน เขียนลง speakers table ของครั้งนี้) **Q3** ข้อจำกัดหน้า 3: ระบบไม่จำตัวตนบุคคลข้ามการประชุมโดยอัตโนมัติ ต้องเลือกคัดลอกรายชื่อ
- ไม่มีคอลัมน์หรือตารางใหม่ในฐานข้อมูล
