# ชุดประเมินคุณภาพรายงานที่ AI ร่าง

เพื่อตอบโจทย์ "ไม่ควรมอบหมายให้ AI สรุปโดยไม่มีเกณฑ์วัด" — เปรียบเทียบรายงานที่ AI ร่างกับ **เฉลยที่คนเขียน** ด้วยตัวชี้วัดที่คำนวณแบบตายตัว
(ไม่ให้ AI ตัดสิน AI) แล้วเทียบ "เกณฑ์ผ่าน" ที่ตกลงไว้ (`metrics.THRESHOLDS`)

## วิธีเพิ่มเคสจริง (ทำอย่างน้อย 3–5 ประชุม)

สร้างโฟลเดอร์ `evaluation/cases/<ชื่อเคส>/` ที่มี 2 ไฟล์

**`transcript.txt`** — transcript ของประชุมจริง (ส่งออกจากหน้าตรวจ transcript แล้ว) บรรทัดละ 1 ช่วง รูปแบบ `ชื่อ: ข้อความ`

**`case.json`**
```json
{
  "title": "ชื่อประชุม",
  "date": "2026-10-01",
  "participants": [{"display_name": "สมชาย ใจดี", "role": "chair"}, {"display_name": "Alice", "role": "secretary"}],
  "expected": {
    "agenda": [
      {"topic": ["งบประมาณ", "เซิร์ฟเวอร์"], "resolution": ["อนุมัติ", ["สองหมื่น", "20,000"]]},
      {"topic": ["ห้องประชุม"], "resolution": null}
    ],
    "action_items": [
      {"keywords": ["เปรียบเทียบ", "ราคา"], "assignee": "Bob", "due_date": "2026-10-05"}
    ]
  }
}
```
- `topic` / `keywords`: คำสำคัญที่ต้องปรากฏในวาระ/งานที่ AI เขียน (ตรงอย่างน้อย 60% ถือว่าตรงกับเฉลย)
- `resolution`: คำสำคัญของมติที่ถูกต้อง หรือ `null` ถ้าวาระนั้น **ไม่มีมติจริง** (ใช้จับกรณี AI แต่งมติขึ้นเอง)
- คำสำคัญหนึ่งตัวเป็นรายการคำพ้องได้ เช่น `["สองหมื่น", "20,000"]` เพราะ AI เขียนตัวเลขได้หลายแบบ
- ตัวเลขวันที่ใน `due_date` เป็น `YYYY-MM-DD` (ค.ศ.), ใส่ `null` ถ้างานนั้นไม่มีกำหนด
- เฉลยต้องเขียนโดยคนที่รู้ว่าประชุมจริงตกลงอะไร **อย่าให้ AI ช่วยเขียนเฉลย**

เคส `example_budget_meeting` เป็น **ตัวอย่างสังเคราะห์** ไว้ทดสอบว่าเครื่องมือทำงาน ไม่ใช่ข้อมูลจริง ห้ามนำตัวเลขไปรายงานเป็นผลประเมินจริง
(ย้ายออกหรือลบเมื่อมีเคสจริงแล้ว)

## รัน

```
venv\Scripts\python evaluation\run_eval.py --repeat 3
```
ผลถูกบันทึกเป็นตาราง Markdown ใน `evaluation/results/` (ไฟล์ถูก ignore จาก git — คัดลอกเก็บเองถ้าจะใช้เป็นหลักฐาน)
ควรใช้ `--repeat 3` ขึ้นไป เพราะ AI ตอบไม่เหมือนกันทุกรอบ (เคยพบมติที่แต่งขึ้นโผล่ 1 ใน 3 รอบ ทั้งที่อีกชุดไม่เจอเลย)

## ตัวชี้วัดและเกณฑ์ผ่านที่เสนอ

| ตัวชี้วัด | ความหมาย | เกณฑ์ |
|---|---|---|
| ครบถ้วนของวาระ | วาระในเฉลยที่ AI สกัดได้ | ≥ 80% |
| ความถูกต้องของมติ | วาระที่มีมติได้มติตรง / วาระที่ไม่มีมติไม่ถูกใส่มติ | ≥ 80% |
| มติที่แต่งขึ้น | วาระที่ไม่มีมติจริงแต่ AI ใส่มติให้ (อันตรายที่สุด) | ≤ 10% |
| ครบถ้วนของงาน | งานในเฉลยที่ AI สกัดได้ | ≥ 80% |
| งานที่ถูกต้อง | งานที่ AI สกัดมามีอยู่จริงในเฉลย | ≥ 80% |
| ผู้รับผิดชอบถูกคน | ในงานที่จับคู่กับเฉลยได้ | ≥ 90% |
| วันกำหนดถูกต้อง | ในงานที่เฉลยมีวันกำหนด | ≥ 90% |
| อ้างอิงไม่ได้ | มติ/งานที่ชั้นตรวจของระบบแจ้งว่าอ้างอิง transcript ไม่ได้ | ≤ 20% |
| ผิดแต่ตรวจไม่เจอ | งานที่ผิดจริงแต่ชั้นตรวจไม่แจ้งเตือน = ช่องโหว่ของระบบ | = 0 |

เกณฑ์เป็นข้อเสนอเริ่มต้น ปรับใน `evaluation/metrics.py` ได้ตามที่ตกลงกับอาจารย์ ตัวชี้วัดที่ไม่มีข้อมูลให้วัดจะแสดง `-`
