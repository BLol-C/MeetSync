# MeetSync — ผู้ช่วยทำรายงานการประชุม Google Meet

บอทเข้าห้อง Google Meet จับคำบรรยายสด (CC) เก็บลงฐานข้อมูล ให้คนตรวจทาน แล้วให้ AI (Gemini) ร่าง
**รายงานการประชุม** ตามแบบฟอร์ม ให้ประธาน/เลขาตรวจ แก้ไข และอนุมัติ ก่อนออกเป็น PDF และส่งงานที่มอบหมายเข้า Google Calendar

```
ตั้งค่าประชุม+บทบาท → บอทจับ CC ลง DB → ตรวจ/แก้ transcript → ยืนยัน → AI ร่างรายงาน → คนแก้ → อนุมัติ → PDF + Calendar
   (แท็บ ①)             (แท็บ ②)             (แท็บ ③)                        (แท็บ ④)
```

หน้าการประชุมมีบรรทัดสถานะ ("ขั้นที่ N จาก 4") และกล่อง "ขั้นตอนต่อไป" ด้านบน บอกว่าตอนนี้ต้องทำอะไร โดยแท็บ ①–④ เป็นแถบนำทางเดียวของหน้านี้

## สถาปัตยกรรม

รัน 2 ส่วนพร้อมกัน (เปิดด้วย `.
un` หรือ `run.ps1`):

| ส่วน | พอร์ต | หน้าที่ |
|---|---|---|
| หน้าเว็บ Streamlit (`streamlit_app.py`, โฟลเดอร์ `ui/`) | 8501 | ทุกอย่างที่ผู้ใช้เห็น (login ด้วย Google ผ่าน `st.login`) ใช้ `service.py` และ `db.py` โดยตรง |
| บริการบอท FastAPI (`app.py`) | 8000 (เฉพาะ localhost) | คุมบอท Playwright ที่เข้า Meet, บันทึกคำบรรยายลง DB, รับ callback ของ Calendar |

สองส่วนคุยกันผ่าน HTTP ด้วย token ลับร่วม (ไฟล์ `.bot_token` สร้างให้เอง) ข้อมูลเก็บใน MySQL ตาราง: `users`, `meetings`,
`speakers`, `transcript_segments`, `summaries` (รายงาน 1 ฉบับต่อ 1 การประชุม), `action_items`, `agenda_items` (รวม 7 ตาราง ไม่มีตารางเทคนิคอื่น)

## ขั้นตอนใช้งาน

1. **สร้างการประชุม** (ปุ่ม "สร้างการประชุมใหม่" ที่แถบข้าง): ลิงก์ Meet, เรื่อง, หน่วยงาน, ครั้งที่, สถานที่ แล้วเพิ่มรายชื่อผู้เข้าร่วมพร้อมบทบาท (ประธาน / เลขา / กรรมการ-สมาชิก / ผู้เข้าร่วมที่ไม่ใช่กรรมการ) ตำแหน่ง (ไม่บังคับ — แสดงในคอลัมน์ "ตำแหน่ง" ของ PDF ถ้าเว้นว่างใช้บทบาทในที่ประชุมแทน) และ **"ชื่อใน Meet"** (ไม่บังคับ — ชื่อที่ Meet แสดงของคนนั้น เช่นชื่อบัญชีภาษาอังกฤษ ไว้จับคู่คนพูดและรายชื่อในห้องให้อัตโนมัติ ไม่ขึ้นในรายงาน ซึ่งใช้ชื่อไทยที่ลงทะเบียนเสมอ) — ถ้าเลือก "การประชุมครั้งก่อน" ไว้ กด "เติมรายชื่อจากการประชุมครั้งก่อน" (หรือติ๊กตอนสร้างประชุม) เพื่อคัดลอกรายชื่อ อีเมล บทบาท ตำแหน่งและชื่อใน Meet มาโดยไม่ต้องกรอกและจับคู่ซ้ำ (ไม่คัดลอกสถานะมา/ไม่มา) และสถานะการเข้าประชุมในแท็บ ① ข้อมูล ผู้ที่ไม่มาใส่ "สาเหตุที่ไม่มา" ได้ (แสดงในรายงาน)
   ใส่ชื่อ **ตรงกับชื่อที่แสดงใน Meet** เพื่อให้ระบบจับคู่คนพูดอัตโนมัติ ใส่อีเมลประธาน/เลขาเพื่อให้เข้ามาตรวจ/อนุมัติด้วยบัญชี Google ของตนได้
2. **เริ่มบอท** (แท็บ ②): กด "เริ่มบอทเข้าห้องประชุม" บอทจะเปิดหน้าต่าง Chrome เข้าห้องและเปิด CC (ล็อกอิน Google ในหน้าต่างนั้นครั้งแรก และต้องมีคนในห้องกดอนุญาตให้เข้า)
   เห็นคำบรรยายสดในแท็บ เมื่อประชุมจบกด "หยุดบอท" ถ้าบอทหลุดกลางประชุม กด "กลับไปบันทึกต่อ" ได้ ข้อความที่จับแล้วไม่หาย
3. **ตรวจ transcript** (แท็บ ③): แก้ข้อความ/ชื่อผู้พูดที่ผิด ลบช่วงที่ไม่เกี่ยว จับคู่ชื่อใน Meet กับผู้เข้าร่วม แล้วกด **ยืนยัน transcript**
   (ถ้ายังไม่ยืนยัน ระบบไม่ยอมให้ AI สร้างรายงาน) ข้อความต้นฉบับยังเก็บไว้ทุกจุดที่แก้ ถ้าต้องแก้อีกกด "กลับไปแก้ transcript"
4. **รายงาน** (แท็บ ④): กด "ให้ AI ร่างรายงาน" → ได้ฉบับร่างที่มีคำเตือนกำกับ (ผู้รับผิดชอบไม่อยู่ในรายชื่อ, วันที่ผิดปกติ, มติที่อ้างอิง transcript ไม่เจอ ฯลฯ)
   **วาระทั้ง 5 แก้ได้**: แต่ละเรื่องมีช่อง "อยู่ในวาระ" (1 แจ้งให้ทราบ / 2 รับรองรายงานครั้งก่อน / 3 เรื่องสืบเนื่อง / 4.1 เรื่องค้างพิจารณา / 4.2 เรื่องพิจารณาใหม่) ส่วนวาระ 5 เรื่องอื่น ๆ เป็นข้อความ
   เรื่องที่ AI สรุปเริ่มต้นอยู่ที่ 4.2 ย้ายไปวาระ 1 เองถ้าเป็นเรื่องแจ้งให้ทราบ (AI ยังไม่จำแนกให้) ถ้าเลือก **"การประชุมครั้งก่อน"** ไว้ในแท็บ ① (เลือกได้เฉพาะที่อนุมัติรายงานแล้ว)
   ตอนกด "ให้ AI ร่างรายงาน" ระบบเติมให้จากฐานข้อมูล (ไม่ผ่าน AI): วาระ 2 หัวข้อรับรองรายงานครั้งที่/วันที่ของครั้งก่อน, วาระ 3 งานที่มอบหมายไว้ครั้งก่อนทุกรายการ, วาระ 4.1 วาระของครั้งก่อนที่ไม่มีมติ —
   ระบบไม่รู้ว่างานไหนเสร็จแล้วหรือเรื่องไหนค้างจริง ต้องตรวจและลบ/แก้เอง มติรับรองรายงานให้กรอกเอง
   แก้ได้ทุกช่อง แล้วกด **อนุมัติ** (ถ้ายังมีคำเตือนต้องกดยืนยันว่าตรวจแล้ว) รายงานที่อนุมัติแล้วถูกล็อก
   ถ้าต้องแก้ต่อกดเปิดแก้ไขรายงานอีกครั้ง (ฉบับที่ AI ร่างเดิมยังเก็บไว้เทียบ)
5. **PDF / Calendar**: ดาวน์โหลด PDF (ก่อนอนุมัติมีลายน้ำ "ฉบับร่าง") และส่งงานที่มีวันกำหนดเข้า Google Calendar หลังอนุมัติ

ส่วนหัวรายงาน (วันที่ เวลา สถานที่ ประธาน เลขา ผู้มา/ไม่มาประชุม) มาจากข้อมูลในระบบ **ไม่ได้ให้ AI สร้าง**
บอทอ่านรายชื่อคนในห้องจากแผง "ผู้คน" ของ Meet ทุก ~60 วินาที (`BOT_PARTICIPANT_SCAN_S`, 0 = ปิด) แล้วตั้ง "เข้าร่วม" ให้คนที่ชื่อตรงกับรายชื่อที่ลงทะเบียนไว้แม้ไม่ได้พูด (ไม่เปลี่ยนคนที่ตั้ง "ไม่มา" ไว้เอง; ชื่อในห้องที่ไม่ตรงกับใครเก็บไว้เป็นผู้เข้าร่วมแยก (พบจาก Meet) ให้ไปจับคู่ที่แท็บ ③ หัวข้อ "ผู้เข้าร่วมที่ยังไม่ยืนยันการเข้าร่วม": แต่ละคนที่ยังไม่ยืนยันเลือกได้ว่าตรงกับชื่อไหนที่เห็นใน Meet หรือกำหนดเองว่ามา/ไม่มา และระบบจำชื่อไว้จับคู่ครั้งหน้า; โครงสร้างรายการคัดจากห้อง Meet ภาษาไทยจริง แต่การที่บอทกดเปิดแผงเองยังไม่ได้ทดสอบกับห้องจริง ถ้าอ่านไม่ได้จะแจ้งในสถานะบอทพร้อมสิ่งที่เห็นในหน้า) ผู้ที่ยังเป็น "ยังไม่ยืนยัน" ตอนกดยืนยัน transcript (คนที่พูดในประชุมเป็น "เข้าร่วม" ให้เองแล้ว) ระบบบันทึกเป็น "ไม่มา" ในฐานข้อมูลให้ตรงกับรายงาน และแจ้งชื่อบนหน้าเว็บ — ถ้ามาจริงแต่ไม่ได้พูด แก้เป็น "เข้าร่วม" ที่แท็บ ① ได้ก่อนอนุมัติ (คนที่เพิ่มทีหลังก็ถูกปรับตอนอนุมัติ)

## ติดตั้งและรัน

ต้องมี Python 3.11+, MySQL/MariaDB (**ต้องสร้างฐานข้อมูลเปล่าไว้เอง** `CREATE DATABASE meetsync CHARACTER SET utf8mb4;` แอปสร้างให้เฉพาะตาราง)

```
python -m venv venv
venv\Scripts\pip install -r requirements.txt
venv\Scripts\python -m playwright install chromium
```

ตั้งค่าใน `.env`:

| ตัวแปร | ความหมาย |
|---|---|
| `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` | การเชื่อมต่อ MySQL |
| `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` | OAuth client (Web) ตัวเดียวใช้ทั้ง login และ Calendar |
| `MEETSYNC_DEV_USER` | (เฉพาะทดสอบ) `อีเมล\|ชื่อ` ข้าม login จริง แถบข้างจะมีป้ายเตือน อย่าตั้งตอนใช้งานจริง |
| `GEMINI_API_KEY` | คีย์ Gemini |
| `GEMINI_MODEL` | (ไม่บังคับ) ค่าเริ่มต้น `gemini-3.6-flash` — รุ่น 2.5 ถูกยกเลิกสำหรับผู้ใช้ใหม่แล้ว |
| `CALENDAR_SEND_INVITES` | `1` = ให้ Google ส่งอีเมลเชิญผู้รับผิดชอบจริง (ค่าเริ่มต้น: ไม่ส่ง กันหลุดไปหาคนจริงตอนเดโม) |
| `MINUTES_PROMPT` | (ไม่บังคับ) ชื่อไฟล์ prompt ใน `prompts/` ค่าเริ่มต้น `minutes_v2` |

Redirect URI ที่ต้องเพิ่มใน Google Cloud Console (Authorized redirect URIs):
- `http://localhost:8501/oauth2callback` — login (Streamlit)
- `http://localhost:8000/auth/google/callback` — เชื่อมต่อ Calendar

(Enable Calendar API ด้วย) หลังล็อกอินครั้งแรก ระบบจะขึ้นหน้า "อนุญาต Google Calendar" ต่อให้ทันที (Google เลือกบัญชีที่ล็อกอินอยู่ให้เอง กดอนุญาตหนึ่งครั้ง
ข้ามไปทำทีหลังที่แท็บรายงานได้) token แยกเก็บรายคนใน DB จึงไม่ต้องทำซ้ำ
ล็อกอินกับ Calendar เป็นสองสิทธิ์แยกกันตามที่ออกแบบไว้ใน Proposal (`st.login` ไม่ส่ง access token ของ Google ให้แอป)

(`run.ps1` สร้างให้เองถ้ายังไม่มีไฟล์ — ไฟล์นี้ไม่ถูก commit)

## ปรับ prompt และแบบฟอร์มโดยไม่แตะโค้ด

- **Prompt ของ AI**: `prompts/minutes_v2.md` (และ `minutes_map_v1.md` สำหรับประชุมยาวที่ต้องแบ่งสกัดก่อน) แก้เป็นไฟล์ข้อความธรรมดา
  ถ้าจะปรับจริงจัง ให้สร้างไฟล์เวอร์ชันใหม่แล้วตั้ง `MINUTES_PROMPT` — รายงานแต่ละฉบับบันทึกชื่อ prompt ที่ใช้สร้างไว้ใน DB
- **แบบฟอร์มรายงาน**: `reports/report_template.py` (หัวข้อ ลำดับส่วน ช่องลงชื่อ ลายน้ำ) และ `reports/pdf_report.py` (ตำแหน่ง/ขนาดตัวอักษร) จัดหน้า A4
  ตามไฟล์แบบฟอร์ม "รูปแบบรายงานการประชุม" ที่ได้รับ ด้วยฟอนต์ TH Sarabun New (`fonts/`) ตารางงานที่ได้รับมอบหมายเป็นส่วนที่ระบบเพิ่มเอง
  ถ้าเปลี่ยนแบบฟอร์ม แก้ที่สองไฟล์นี้

## การควบคุมคุณภาพ AI

1. บังคับรูปแบบผลลัพธ์ด้วย response schema ของ Gemini (ไม่ใช่แค่ขอ JSON ใน prompt)
2. ทุกมติ/งานต้องมีข้อความอ้างอิงที่คัดลอกจาก transcript — ระบบตรวจว่าอ้างอิงนั้นมีอยู่จริงใน transcript (ทนต่อการเว้นวรรคภาษาไทย) ไม่เจอ = เตือน
3. ผู้รับผิดชอบต้องอยู่ในรายชื่อผู้เข้าร่วม (ตัดคำนำหน้า คุณ/นาย/ดร. ก่อนเทียบ), วันที่/เวลาต้องอ่านได้และสมเหตุผล
4. คนต้องตรวจและกดอนุมัติเสมอ — AI ไม่มีทางออกรายงานฉบับจริงเอง
5. **ชุดประเมิน** `evaluation/`: เทียบรายงานที่ AI ร่างกับเฉลยที่คนเขียน คำนวณตัวชี้วัด 9 ตัว (ความครบของวาระ/งาน, ความถูกต้องของมติ, มติที่แต่งขึ้น,
   ผู้รับผิดชอบ/วันที่ถูกต้อง, อ้างอิงไม่ได้, งานที่ผิดแต่ระบบตรวจไม่เจอ) เทียบเกณฑ์ผ่าน — ดู `evaluation/README.md`

   ```
   venv\Scripts\python evaluation\run_eval.py --repeat 3
   ```

### ทดสอบความเสถียร 1 ชั่วโมงขึ้นไปกับห้อง Meet จริง (ต้องทำเอง)

ตัวจำลองพิสูจน์ได้แค่ตรรกะของตัวจับคำบรรยาย **ไม่ใช่ Meet จริง** ให้ทดสอบจริงดังนี้
1. เปิดห้อง Meet ที่ไม่ติดเพดาน 60 นาที (ห้องฟรีจำกัด 60 นาทีเมื่อมีผู้เข้าร่วม 3 คนขึ้นไป) ให้มีคนพูดสลับกันเป็นช่วงๆ ตลอด
2. เริ่มบอทจากแท็บ ② ของหน้าเว็บ แล้วเปิดอีกหน้าต่าง PowerShell: `powershell -ExecutionPolicy Bypass -File tools\proc_monitor.ps1 -Minutes 95`
3. หลังจบ: `powershell -File tools\proc_monitor.ps1 -Summarize soak_xxxx.csv` — ดูว่าหน่วยความจำ python+chrome ช่วงท้ายไม่สูงกว่าช่วงต้นเกิน ~15%
   และเทียบจำนวนช่วงคำพูดใน DB กับที่พูดจริง

## ข้อจำกัดที่ควรรู้ (ยังไม่ได้พิสูจน์ / ไม่ได้ทำ)

- **ทดสอบกับ Google Meet จริงแล้วบางส่วน** (เปิด CC หลังผู้จัดอนุญาต ข้อความไม่ซ้ำ เข้าห้องซ้ำได้) แต่ **ยังไม่เคยทดสอบต่อเนื่อง 60 นาทีขึ้นไป** และฟีเจอร์ใหม่ (สาเหตุที่ไม่มา บทบาทผู้เข้าร่วม PDF แบบใหม่) ยังไม่ได้ซ้อมกับ Meet จริงครบสายงาน
  ตัวจับ CC อ่านชื่อ class ของ Meet ที่ถูกอำพราง ถ้า Meet เปลี่ยน DOM ต้องปรับ selector ใน `bot/meet_engine.py`
- ทดสอบการสร้างรายงานกับ Gemini จริงแล้วบนเคสสังเคราะห์เคสเดียวเท่านั้น (ดู `evaluation/`) ต้องเพิ่มประชุมจริงพร้อมเฉลยถึงจะอ้างผลได้
- รันได้ทีละห้องประชุมต่อเซิร์ฟเวอร์ (บอทตัวเดียว) และไม่มีหน้า admin/dashboard สถิติ (ตัดออกตามขอบเขต) มีเฉพาะสิทธิ์: เจ้าของ และประธาน/เลขาตามอีเมล
- ถ้าแก้รายงานหลังส่งเข้า Calendar แล้ว event เดิมใน Calendar จะไม่ถูกลบ/อัปเดตอัตโนมัติ
- เซิร์ฟเวอร์ออกแบบสำหรับเครื่องเดียว/เดโม (HTTP localhost) ไม่ได้ทำการ deploy จริง
- login และ Calendar เคยทดสอบกับ Google จริงบนต้นแบบก่อนปรับปรุง (ตาม Proposal) แต่ยังไม่ได้ยืนยันซ้ำกับโค้ดปัจจุบัน
- ไม่มีระบบอัปเกรดโครงสร้างฐานข้อมูล (ลบ migration ออกแล้ว): ถ้าแก้ `_SCHEMA` ใน `db.py` ต้องลบฐานข้อมูลแล้วสร้างเปล่าใหม่ ข้อมูลเดิมจะหาย
  (หรือเก็บข้อมูลไว้โดยรัน ALTER เอง เช่น ฐานข้อมูลที่สร้างก่อนมีวาระ 5 หมวดและการประชุมครั้งก่อน:
  `ALTER TABLE agenda_items ADD COLUMN section VARCHAR(20) NOT NULL DEFAULT 'consider_new' AFTER order_no;`
  `ALTER TABLE speakers ADD COLUMN position VARCHAR(100) NULL AFTER absence_reason;`
  `ALTER TABLE meetings ADD COLUMN previous_meeting_id INT NULL AFTER status;`
  `ALTER TABLE meetings ADD CONSTRAINT fk_meetings_previous FOREIGN KEY (previous_meeting_id) REFERENCES meetings(meeting_id) ON DELETE SET NULL;`)
- AI ยังไม่จำแนก "เรื่องแจ้งให้ทราบ" กับ "เรื่องเสนอเพื่อพิจารณา" ให้ เรื่องที่ AI สรุปทั้งหมดเริ่มที่ข้อ 4.2 ผู้ใช้ย้ายไปวาระ 1 เองได้ในแท็บ ④
- คำไทยคำเดียวที่กว้างกว่าช่องในตาราง PDF (เช่น ชื่อยาวมากในช่องแคบ) ยังถูกตัดกลางคำได้ เพราะไม่มีที่ตัดอื่น
